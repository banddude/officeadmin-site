# OfficeAdmin Site Module

Date: 2026-05-20

## Purpose

Owns the public landing + documentation site at
[officeadmin.io](https://officeadmin.io). The site is the buyer-facing
storefront for OfficeAdmin and the live, auto-generated documentation
surface for every other AIVA module — same data, two presentations.

## What It Does

1. **Landing page (`/`)** — hand-drawn comic-style marketing page with an
   animated inbound pipeline ("watch a real message become a reply"),
   interactive system graph of all ~70 modules in 10 clusters, mobile
   drill-down view, trust-tier explanation, dossier examples, comparison
   table, FAQ.
2. **Docs page (`/docs.html`)** — auto-rendered card grid of every module
   in `~/.aiva/modules/`, searchable + filterable, with full `MODULE.md`
   expansion per module.
3. **Module catalog (`modules-docs.json`)** — generated by
   `bin/generate-docs.py` from `MODULE.md` + `module.json` + `bin/` of
   every module on disk. Consumed by the graph + docs page + cards on the
   landing page.
4. **Auto-regen on file change** — `bin/watch-modules.sh` runs under
   launchd (`com.officeadmin.site.watch-modules`); fswatch on
   `~/.aiva/modules/` triggers regeneration whenever any `MODULE.md`,
   `SKILL.md`, `module.json`, or `bin/*` file changes. Output goes
   straight into the repo so the next `git push` ships the change.

## Boundaries

This module owns:

1. The marketing landing page, docs page, and module-catalog generator.
2. The shell + launchd plumbing that keeps the catalog fresh on disk.

It does NOT own:

1. The `officeadmin/` system atlas — that's a separate generator
   (`scripts/generate-officeadmin-map.mjs`) on its own hourly launchd
   cron that auto-commits.
2. The `architecture.html` interactive diagram — legacy content
   preserved as-is.
3. Any module's own documentation — the generator only *reads* MODULE.md,
   never writes to it. To change what shows up on the site for a given
   module, edit that module's own `MODULE.md` or `module.json`.

## Public Surface

- `bin/generate-docs.py` — regenerate `modules-docs.json` on demand.
- `bin/watch-modules.sh` — long-running fswatch wrapper (called by launchd).

## Runtime

- Machine: `laptop` (the watcher only runs on the laptop; aiva doesn't
  need to run it because the laptop syncs the repo via git).
- Launchd: `com.officeadmin.site.watch-modules`
  (plist at `~/.aiva/ops/launchd/com.officeadmin.site.watch-modules.plist`,
  symlinked into `~/Library/LaunchAgents/`).
- Logs: `~/.aiva/ops/logs/officeadmin-site/watch-modules.log`.

## Deployment

GitHub Pages serves the `main` branch of
[github.com/banddude/officeadmin-site](https://github.com/banddude/officeadmin-site),
and a Cloudflare Worker (`officeadmin-router`) proxies officeadmin.io →
GitHub Pages.

Workflow:

```bash
cd ~/.aiva/modules/officeadmin-site
# (catalog auto-updates from the watcher; marketing copy edits go in index.html)
git add -A && git commit -m "..." && git push
# → GH Pages rebuilds (~30-60s) → CF Worker caches for 5min → live
```
